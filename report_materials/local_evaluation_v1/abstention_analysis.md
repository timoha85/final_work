# Причины manual_review и корректность протокола

Ошибки API/JSON/evidence_id и нарушение лимита повторной проверки — разные события. Валидный JSON не означает, что модель соблюла ограничение на инструменты. Все исходы остаются в общем знаменателе.

| Метод | Автоматически | Повторный запрос сверх лимита | Abstention аналитика → merge | Прямой abstention модели | Ошибка API/валидации |
|---|---:|---:|---:|---:|---:|---:|
| C | 12 | 5 | 0 | 0 | 1 |
| D | 0 | 18 | 0 | 0 | 0 |
| E | 3 | 15 | 0 | 0 | 0 |

Отказ recheck_protocol_stop сформирован оркестратором при повторном запросе или конкуренции запросов аналитиков за единственную проверку. Новая проверка сверх лимита не выполнялась. Это несовместимость поведения модели с выбранной политикой координации, а не подтверждение атаки и не обязательно осторожное reasoning.

Для D одной финальной строки An analyst abstained недостаточно: анализируются raw request_check аналитиков. Если несколько запросов превышают общий лимит, причина отнесена к recheck_protocol_stop; в остальных случаях — к conservative_analyst_merge. Это отчётная классификация причин, она не меняет итоговые прогнозы.

В D правило conservative_analyst_merge распространяет abstention любого аналитика на итог. Поэтому низкая автоматизация D может определяться выбранной политикой объединения и обработки инструментов, а не только классификационным reasoning.

Результат характеризует данную модель, prompts и конкретный bounded protocol. Улучшение инструкций управления инструментами возможно только в следующем exploratory эксперименте с новым run_id; ответы этого прогона вручную не исправлялись.
