# Техническое описание для раздела Methods

Проект — исполняемый Python CLI без веб-интерфейса. Локальный PAD вычисляется на CPU через ONNX Runtime. Входы для языкового анализа фильтруются до typed Evidence с evidence_id, group, provenance, observed_by, status, values. Real media остаются на машине, LLM получает числовые и категориальные агрегаты. Нет персональных данных в synthetic telemetry; лица не отправляются провайдеру.

Реализованы пять методов: бинарный PAD; фиксированные правила; один LLM; два LLM-аналитика с программным merge; два LLM-аналитика с LLM-верификатором. Под «реализовано» понимается наличие кода, а статус фактического исполнения каждой ветви определяется только results/<run_id>/ и STATUS.md. Без API сравнение LLM не измерено. Test doubles проверяют исполнение оркестратора и не используются в таблицах качества.

Отдельные роли анализируют свои группы evidence и формируют JSON Decision; верификатор сравнивает с исходными evidence, а не только с чужими пересказами. Одна разрешённая addressed recheck пересчитывает известные поля; она помечается derived и не считается новым наблюдением. Число вызовов, проверок, известные токены, сетевые и форматные ошибки сохраняются. Политика неисправности — manual_review, а не allow.

Сравнение использует общий кэш локального visual inference. Загрузка модели выполняется один раз, внутри source timer учитываются inference и запись кадров; triage timer начинается после подготовки AgentInput. Метод B и агентные методы видят одинаковый исходный пул групп, но B использует только часть полей в формуле решения; это оговорённая простота baseline. Каждый run хранит конфигурацию и SHA-256 кода, протокола, инцидентов, меток и кэша. Генератор детерминирован по seed, LLM не обязан быть детерминирован даже при temperature=0.

Оценочный набор полусинтетический. Все цифры статьи следует брать из автоматически построенных CSV и results_summary.md конкретного run_id. Связанные контекстные повторы не являются независимыми биометрическими наблюдениями. Отчёт должен различать качество триажа сценариев, качество исходного визуального PAD и устойчивость реального канала; последний аспект данным экспериментом не устанавливается.
