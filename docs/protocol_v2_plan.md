# Exploratory follow-up: протокол v2

Зафиксировано до debug/evaluation v2. Исходный local_evaluation_v1 уже просмотрен; новый анализ не является независимым тестом на неизвестных данных. Гипотеза: state-dependent доступность действий уменьшит технические/координационные отказы без роста опасных allow. Улучшение не предполагается заранее.

Снимок v1: snapshots/protocol_v1_before_v2.zip + SHA-256 manifest. Исходные triage/agents.py, schemas.py, rules.py, результаты, таблицы и prompts не редактируются. V2 находится в отдельном triage/protocol_v2.py; SYSTEM/ROLES импортируются побайтно из v1. A/B не перезапускаются и не изменяются: их прежние результаты на тех же 18 ID служат неизменным ориентиром.

## Точный policy diff
- FinalDecision наследует Decision, но request_check имеет Literal['none']; эта JSON Schema подаётся в constrained decoding И Pydantic-валидацию.
- C: предварительный ответ с доступными инструментами; при запросе — одна проверка и один ответ в финальной схеме. Без запроса предварительный ответ с none допускается как окончательный.
- D: два предварительных аналитика. Фиксированная очередность распределения общей проверки: **context, затем visual**, первый non-none. Это правило не читает ground truth, классы или scores. Дополнительный LLM-вызов получает только выбранный аналитик и только финальную схему. Другой предварительный вывод сохраняется; его невыполненный запрос логируется, но сам по себе не вызывает review. Никакой ручной смены класса/маскировки raw response нет. Merge классов импортирован без изменений из v1. Максимум 3 LLM-вызова, как в фактической ветви D v1.
- E: аналитики сразу получают финальную схему без инструментальных запросов; verifier может запросить одну проверку, после неё финальная схема. Максимум 4 вызова.
- Содержательный manual_review разрешён во всех схемах. Ошибка JSON/ссылок/сети либо отказ запрошенного инструмента дают системный review, не allow. Класс из невалидного JSON не извлекается. Уточнение fail-closed при техническом отказе — явно зафиксированная часть реализации протокола, не эвристика классификации.

Это **совместное** изменение ограничений схемы, stage-инструкций и политики распределения запросов; эффект одной компоненты не изолируется. Содержательные инструкции классификации, Qwen/GGUF, temperature=0, seed=8217, max_tokens=600, timeout=40 с, общий потолок 4 вызова/2400 выходных токенов и одна проверка сохраняются. Прежний D максимум 3, C максимум 2. Context=8192, CPU threads=6, runtime b12032 без изменений. Никаких платных/удалённых запросов.

## Проверки и заморозка
Unit/debug до evaluation: финальная схема исключает запрос; конкуренция; не более одной выполненной проверки; содержательный review; невалидный JSON; отказ инструмента; лимит вызовов; сохранение частичного запуска. Затем один реальный debug-прогон на двух заранее выбранных случаях: первый complete debug из сохранённого списка и первый по ID debug с PAD fault. Новые prompts/схемы/код замораживаются SHA-256 после debug. Нельзя менять их по evaluation и перезапускать для лучшей метрики.

## Оценка
Один run local_protocol_v2, только C/D/E на неизменных data/local_evaluation_selection.json: 18 ID, 6 на класс, 8 источников. Все отказы в знаменателях. Наблюдения повторные, не новые независимые данные. Время/вызовы/токены фактические; API cost 0. Фиксированный порядок C/D/E, прогрев prefix cache ограничивает сравнение latency. Не заявлять статистическую значимость.

Таблица до/после: macro-F1, атаки allow/12, benign reject/6 и escalate/6 отдельно, review/18, coverage, число верных auto, причины review, вызовы, токены, время. Парные переходы включают отдельно **v1 review → v2 ошибочный allow атаки**, новые и устранённые опасные allow, изменения benign reject/escalate. Проверить, что меньший review не маскирует ухудшение безопасности.

Если часовой бюджет исчерпан: checkpoint после каждого метода, статус partial, явные завершённые пары method/incident. Не выдавать неполный метод за n=18 и не объединять разные подмножества. Сравнение для partial только на точно совпадающих ID конкретного метода с явным знаменателем; общий вывод по n=18 только при полном завершении.
