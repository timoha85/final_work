# Протокол v1 — 2026-11-02

Зафиксирован до оценочного прогона. Исследовательский вопрос: улучшает ли разделение анализа визуальных свидетельств и канала между LLM-ролями триаж по сравнению с правилами и одной LLM при одинаковых исходных свидетельствах? Преимущество не предполагается заранее.

## Данные и разделение
Отладка: три демонстрационных кадра официального minivision-ai/Silent-Face-Anti-Spoofing (метки примеров real/fake, не независимый бенчмарк). Оценка: публичный sample AxonData/Display_replay_attacks на Hugging Face: 5 real JPG и 5 screen replay видео; карточка CC BY 4.0. UniAttackData проверен, требует соглашения и одобрения, не используется. Метки поставщика не являются результатом независимой экспертизы.

Единица: инцидент с 1–3 кадрами и синтетическим контекстом. Дочерние инциденты одного изображения/видео зависимы; все остаются в одном split. Межсубъектная независимость не гарантирована: идентификаторы людей не предоставлены. Все видео и фото AxonData остаются в оценке. Оценка планируется на 60 инцидентах, по 20 на сценарный класс, но только 10 уникальных медиаисточниках. Отладочный пилот — 10 инцидентов. Никакой статистической значимости по числу повторно использованных изображений не заявлять.

Истинная метка сценария хранится отдельно от исходной визуальной метки. Injection — сценарная подмена доставки ранее полученного материала, включая real фото; это не реальные зарегистрированные внедрения. Клиентские и серверные поля — синтетические, даже если по смыслу описывают серверное наблюдение. История содержит только события до текущего.

## Методы, решения и бюджет
A: PAD, argmax из трёх выходов, индекс 1 означает live; бинарные live/spoof, без определения типа атаки. Ошибка/отсутствие PAD → manual_review. Баллы softmax не калиброваны. B: фиксированные правила (подтверждение канала двумя независимыми по смыслу полями; иначе PAD; неоднозначность → review). C: одна LLM со всеми свидетельствами. D: два аналитика, программное консервативное объединение: совпадение классов либо один attack и другой bona_fide → attack; конфликт двух типов attack / abstention → review. E: те же два аналитика, отдельный LLM-верификатор с исходными свидетельствами, максимум один запрос разрешённого инструмента.

C/D/E: одна модель, temperature=0, общий предел 4 вызова и 2400 выходных токенов на инцидент/метод; каждому вызову максимум 600 токенов, таймаут 40 секунд, без сетевых повторов. C может запросить одну проверку и повторный вывод; D аналитики могут запросить в сумме одну проверку; E проверку запрашивает только верификатор. Инструмент проверки повторно агрегирует уже известные факты, не является новым независимым свидетельством. Цена неизвестна без проверенного прайса. До платного пилота требуется заданный пользователем лимит. После пилота объём можно сократить только по времени/бюджету, не по качеству, с записью причины. Ненастроенные методы не заменять правилами и не включать в таблицу измеренного качества.

Рекомендации: bona_fide/live → allow, attack/spoof → reject, manual_review → escalate. Это рекомендации без действий над аккаунтом. Недостаточность данных, сбои и невалидные выводы сохраняются; не считаются доброкачественным результатом.

## Метрики
Пропуск атак = allow среди всех PA+injection. Ложная тревога = reject или escalate среди всех bona_fide (дополнительно reject отдельно). Review по каждому истинному классу; coverage = автоматические решения / все инциденты. Для B–E precision/recall/F1 по трём классам, abstention даёт FN истинному классу; macro-F1 — среднее трёх F1, zero division=0. Отдельно selective accuracy среди автоматических решений и её знаменатель. Матрица 3×4 с manual_review. Для A бинарные precision/recall/F1, selective accuracy и матрица 2×3 считаются по исходной визуальной метке live/spoof, а общие показатели рекомендаций — по сценарной метке, включая injection. Эти задачи не смешиваются. Не исключать ошибки и таймауты. Знаменатели сохранять в CSV. Время PAD и триажа отдельно, токены и вызовы фактические; общие аналитические вызовы D/E повторно не выдавать за независимые наблюдения.

## Стресс-сценарии и заморозка
Нормальные benign, PA, injection; benign с виртуальной камерой/аномалией; injection без заметной сигнатуры; противоречия PAD/канал; пропуски; контролируемый отказ PAD; текстовая prompt injection в недоверенном поле. Генератор вероятностный, не копирует пороги правил. Путь источника, имя сценария, визуальная метка, разметка и split не передаются LLM. Любые изменения правил/промптов после оценки маркировать exploratory с новым run_id. Проверка одной текстовой атаки не доказывает абсолютной защиты.
